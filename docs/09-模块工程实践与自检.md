# 模块工程实践：纯反射 hook、自检与反查

> 本篇不讲 API 用法（01 已经讲透），讲的是**怎么把这类模块做稳**：
> 怎么不依赖第三方 SDK、怎么在看不到屏幕的情况下证明 hook 生效、怎么反查框架的真实行为。

## 1. 纯反射 hook 第三方 SDK

### 传统做法的问题

原版锤锤把高德定位 SDK 整个打进模块 APK（`implementation` 而不是 `compileOnly`），
结果 4.3MB，而且 SDK 版本一变就可能编译不过。

### 本项目的做法

模块里**一个高德类都没有**，全部反射：

```java
ClassLoader cl = param.getClassLoader();
Class<?> clientCls   = Class.forName("com.amap.api.location.AMapLocationClient", false, cl);
Class<?> listenerCls = Class.forName("com.amap.api.location.AMapLocationListener", false, cl);
Class<?> locationCls = Class.forName("com.amap.api.location.AMapLocation", false, cl);

// 1) 直接返回伪造对象
Method m = clientCls.getDeclaredMethod("getLastKnownLocation");
m.setAccessible(true);
hook(m).intercept(chain -> {
    Profile p = ConfigReader.current();
    if (p == null || !p.enabled) return chain.proceed();
    Object fake = buildFake(locationCls, p);
    return fake != null ? fake : chain.proceed();
});

// 2) 包住回调，把伪造值刷到真实对象上
for (Method m2 : clientCls.getDeclaredMethods()) {
    if (!"setLocationListener".equals(m2.getName())) continue;
    Class<?>[] pts = m2.getParameterTypes();
    if (pts.length == 0 || !pts[0].isAssignableFrom(listenerCls)) continue;
    hook(m2).intercept(chain -> {
        Object original = chain.getArg(0);
        if (original == null) return chain.proceed();
        Object proxy = Proxy.newProxyInstance(cl, new Class[]{listenerCls},
                (p, method, args) -> {
                    if ("onLocationChanged".equals(method.getName())) {
                        copyFields(buildFake(locationCls, ConfigReader.current()), args[0]);
                    }
                    return method.invoke(original, args);
                });
        return chain.proceed(new Object[]{proxy});
    });
}
```

**收益**：

- APK 从 4.3MB 降到 **50KB**
- 不需要高德 API key、不需要 so
- SDK 升级不受影响：`setXxx` 找不到就跳过，不会崩

**代价**：

- 所有反射点都要 `try/catch`，失败只打日志不抛
- 方法名/类名是字符串常量，目标 App 混淆了就失效（高德 SDK 是公开 API，一般不混淆）

**注意**：`Class.forName(name, false, cl)` 第二个参数传 `false`，避免触发类初始化（有些 SDK 在 `<clinit>` 里做事）。

## 2. 自检：装完 hook 立刻证明链路通

**背景**：钉钉开了 `FLAG_SECURE`，截图全黑、无障碍树为空，考勤页根本点不进去。
如果只靠"等真实定位回调"来验证，可能几天都等不到一次。

**做法**：hook 安装完成后，立刻用当前配置构造一个伪造对象，再复制到空白对象上，打印结果：

```java
// AmapHooks.install() 末尾
Profile p = ConfigReader.current();
if (p != null) {
    Object fake = buildFake(locationCls, p, true);   // 带漂移
    Object real = newInstance(locationCls);          // 空白对象
    int fields = copyFields(fake, real);
    Logger.i(String.format(Locale.US,
            "自检通过: 复制字段 %d，坐标 %.6f,%.6f，地址 %s",
            fields, getDouble(real, "getLatitude", 0),
            getDouble(real, "getLongitude", 0), getString(real, "getAddress", "")));
}
```

日志里出现这行，就说明：

- 类加载成功（`Class.forName` 没抛）
- 反射构造成功（无参/字符串构造可用）
- 43 个 setter 全部调用成功
- 漂移算法正常（坐标和配置差几米）

**不依赖任何真实回调**，装完包启动目标 App 就能看到。

**这是本项目最有用的一个实践**：把"能不能用"从"等用户去点考勤页"变成"启动就能看"。

## 3. 反查框架实现，别靠猜

遇到"官方文档没写"的行为，直接反编译看实现，比试错快得多。

**本项目的三个例子**：

### 3.1 `openRemoteFile` 的真实路径

```bash
# 1. 把 daemon.apk 拉出来
adb pull /data/adb/modules/zygisk_lsposed/daemon.apk
# 2. 反编译（只反 dex，跳过资源，快）
jadx -d daemon_src --no-res daemon.apk
# 3. 搜关键 API
grep -rn "ParcelFileDescriptor" daemon_src/sources | head
```

顺着 `onTransact` 的 case 3/4 找到 `c6.q(...)`，再跟到根目录常量，就拿到了
`/data/adb/lspd/modules/<userId>/<pkg>/files/`。

### 3.2 `getRemotePreferences` 为什么空

同一次反编译里，搜 `HashMap` 相关的方法，看到它查的是 `SQLiteDatabase`（`this.f94a.query`），
立刻明白：**数据源是 daemon 的数据库，不是模块的 prefs 文件**。

### 3.3 客户端和服务端的分界

`framework.dex` 是注入到目标进程的客户端（`XposedInterfaceWrapper`），
`daemon.apk` 是服务端。反编译时**两个都要看**，否则会以为某个方法是本地实现。

## 4. 构建：GitHub Actions 无 wrapper 方案

**问题**：本地没有 Gradle，`gradle wrapper` 生成不了 `gradle-wrapper.jar`。

**解法**：CI 里用 `gradle/actions/setup-gradle` 直接指定版本，不需要 wrapper：

```yaml
- uses: actions/setup-java@v4
  with:
    distribution: temurin
    java-version: '17'

- uses: gradle/actions/setup-gradle@v4
  with:
    gradle-version: '8.9'      # 与 AGP 8.7.3 匹配

- run: gradle :app:assembleRelease --no-daemon
```

**配套**：

- 固定 keystore（仓库里放一个，`signingConfig` 指向它），否则每次 CI 签名不同，覆盖安装会失败
- 自动发 `latest` release，方便设备匿名下载（artifact 需要登录）
- 下载 URL 加 `?ts=$(date +%s)` 破 CDN 缓存

**本地类型检查**（不跑 Gradle）：

```bash
javac -nowarn -proc:none --release 17 \
  -cp "android-35/android.jar:libxposed-api-102.jar" \
  -d out $(find app/src/main/java -name "*.java") typecheck/R.java
```

`R.java` 用脚本从 `res/` 生成（本项目有 `typecheck/gen_r.py`），
这样改完代码本地 2 秒就能发现语法/类型错误，不用等 CI。

## 5. 调试纪律

### 5.1 后台优先，GUI 最后

能用命令解决的，绝不点屏幕：

| 需求 | 命令 |
|---|---|
| 装包 | `pm install -r /data/local/tmp/x.apk`（**先复制到 `/data/local/tmp`**，`/sdcard` 上 system_server 读不了） |
| 启停 | `am force-stop` / `monkey -p pkg -c android.intent.category.LAUNCHER 1` |
| 看日志 | `logcat -d -s LSPosedFramework:V \| grep ChuiChui` |
| 看配置 | `content call --uri content://... --method config` |
| 看文件 | `nsenter -t 1 -m cat /data/user/0/.../files/x.json` |

**`nsenter` 那个技巧**：KernelSU 的 `su` shell 运行在受限 mount namespace 里，
`/data/user/0` 下大部分 App 目录看不到。加 `nsenter -t 1 -m` 进 init 的 namespace 就能看到全部。

### 5.2 日志代替眼睛

目标 App 有 `FLAG_SECURE` 时，截图和 `observe_screen` 都是黑的。
这时候**把关键数据写进日志**，比想办法看屏幕有效得多：

- 配置来源（哪条通道成功了）
- 字段覆盖数（hook 生效程度）
- 每次定位的坐标 + 偏移（漂移是否工作）

本项目把日志写到 `/sdcard/Download/chuichuihook/hook.log`，
用文件管理器就能看，不用连电脑。

### 5.3 一次只改一个变量

排查通道问题时，容易一次改三个地方（包名、通道、权限），结果不知道哪个生效。
本项目踩过：改了 targetSdk、加了 `<queries>`、又换了通道，最后发现是包可见性。

**正确做法**：每条通道单独打日志，用 `配置来源: xxx` 区分，改一个看一次。

### 5.4 别改 LSPosed 数据库

03 第 16 条说过，这里再强调：`modules_config.db` 里改状态，daemon 内存有缓存，
外部改会被覆盖，严重时配置损坏。要启用模块就让用户在管理器里点两下。

## 6. 上线前 checklist

- [ ] `META-INF/xposed/` 三个文件都在 APK 里（`unzip -l` 确认）
- [ ] `module.prop` 的 `targetApiVersion` 和实际用的 API 匹配
- [ ] 所有 `hook()` 都包了 `try/catch`，失败只打日志
- [ ] `chain.getThisObject()` 判空（静态方法为 null）
- [ ] 多进程 App：`onPackageReady` 按包名去重
- [ ] 配置读取有回退链，且成功后回写持久化
- [ ] 有自检日志，装完就能判断是否生效
- [ ] 日志写到用户能直接看到的位置
- [ ] 签名固定，覆盖安装不丢 LSPosed 状态
- [ ] README 写清楚：包名、目标 App、已知限制、怎么验证

## 7. 一句话总结

**把"能不能用"变成"日志里能不能看到"，把"猜框架行为"变成"反编译看实现"。**
这两件事做到了，模块开发的大部分时间就不会浪费在盲试上。
